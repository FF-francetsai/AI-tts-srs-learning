## 二、詳細測試案例

### TC-01  守護者 Persona 載入完整性（P0）
- **前置**：10 隻守護者 persona 檔位於 `/workspace/03_Skill_Engine/Skills/npc-persona-forge/personas/`。
- **步驟**：
  1. 啟動 `rpg.html`，等待主選單。
  2. 進入「守護者圖鑑」，逐隻點擊 10 隻 sprite。
  3. 觀察每隻是否顯示：姓名／星等／教學主題／對應關卡入口。
- **預期結果**：
  - 10/10 全部可載入；無 console error。
  - 每隻的 `teachingTopic` 與關卡入口字串非空。
  - 圖片 sprite 32×32 PNG 正常顯示，無破圖。
- **不通過處置**：檢查 persona YAML/JSON schema 與 `persona_loader.js` 欄位對應。

### TC-02  守護者戰鬥與教學提示語一致（P0）
- **前置**：進入任一守護者關卡。
- **步驟**：
  1. 與守護者對話 3 輪。
  2. 觸發戰鬥（答題）1 次。
  3. 戰鬥結束觀察結算動畫與教學評語。
- **預期結果**：
  - 對話用詞與 persona 檔的 `speakingStyle` 一致。
  - 答錯時觸發的「提示語」與 `hintPattern` 對齊。
  - 結算畫面顯示該守護者專屬鼓勵句。
- **不通過處置**：退回 persona 草稿至 QA 審核閘重審。

### TC-03  章節切換與邊界碰撞（P0）
- **前置**：玩家位於 Stage 1 入口。
- **步驟**：
  1. 向東走到座標 (maxX, y) 嘗試超出地圖。
  2. 觸發 Stage 1 → Stage 2 傳點。
  3. 切回 Stage 1，確認玩家位置回到上一存檔點。
- **預期結果**：
  - 出界時角色被牆擋回（無穿牆）。
  - 切章節時 `currentStage` 狀態正確寫入 save slot。
  - 切回後 NPC 與道具狀態與切出前一致。

### TC-04  Tile 渲染效能（P1）
- **前置**：單一章節內同時渲染 30 棵樹 + 20 顆星塵 + 5 隻 NPC。
- **步驟**：
  1. Chrome DevTools → Performance 錄製 30 秒。
  2. 觀察 FPS 與 draw call 數。
- **預期結果**：
  - FPS ≥ 50（中階筆電）。
  - 同一 sprite 不重複載入（atlas 快取命中）。
- **不通過處置**：考慮 sprite atlas 合併或 canvas 分層。

### TC-05  道具三態正確性（加成/解鎖/收集）（P0）
- **前置**：背包系統可用。
- **步驟**：
  1. 撿取「星塵碎片」×3，確認為「收集」態。
  2. 裝備「光之披風」，確認為「加成」態（+10% 教學分）。
  3. 取得「守護者徽章」，確認為「解鎖」態（解鎖新章節）。
- **預期結果**：
  - 三種 `itemState`（collect / buff / unlock）獨立且互斥。
  - 卸下裝備時加成即時消失。
  - 解鎖道具無法再被消耗。

### TC-06  道具與任務觸發連動（P0）
- **前置**：身上持有「守護者徽章」。
- **步驟**：
  1. 與 NPC「仲裁者」對話，選擇出示徽章。
  2. 確認觸發支線任務「重返星門」。
- **預期結果**：
  - 任務狀態由 `available` → `active`。
  - 徽章不被消耗（屬於「解鎖」態）。
  - 後續章節傳點開啟。

### TC-07  任務前置條件鏈（P0）
- **前置**：主線 A「星際啟程」尚未完成。
- **步驟**：
  1. 嘗試接取支線 B「守護者試煉」。
  2. 嘗試接取主線 C「星雲審判」。
- **預期結果**：
  - B 因前置 A 未完被鎖，提示「請先完成星際啟程」。
  - C 為主線，無前置可直接接取。
  - 完成 A 後 B 自動 `unlocked`，無需重整頁面。

### TC-08  NPC 觸發時序與重入保護（P1）
- **前置**：站在 NPC 觸發區內。
- **步驟**：
  1. 連續 5 次按下「互動」鍵（每 100ms）。
  2. 觀察對話框是否堆疊。
- **預期結果**：
  - 同 NPC 同時僅存在一個對話實例。
  - 第 2 次起按鍵被忽略直至對話結束。
- **不通過處置**：於 `core_functions.md` 的 `triggerNPC()` 加 reentrancy guard。

### TC-09  存檔/讀檔後狀態一致性（P0）
- **前置**：完成 TC-01~08 後，存檔至 slot 1。
- **步驟**：
  1. 關閉分頁、重新開啟 `rpg.html`。
  2. 讀取 slot 1。
- **預期結果**：
  - 角色位置、章節、背包、任務日誌四項 100% 還原。
  - 無 zombie 任務（顯示 active 但實際已被取消）。

### TC-10  治理法庭併發回歸（P1）
- **前置**：`rpg-governance.js` 已上線。
- **步驟**：同時觸發「答題結算」與「治理投票結算」。
- **預期結果**：兩者動畫不打架，分數加總正確。
- **不通過處置**：用 requestAnimationFrame 排隊或獨立的 canvas layer。

## 三、潛在風險與緩解措施

### R-01  美術資產管線不穩（Z-Image Turbo 尚未量產驗證）
- **風險**：29 隻 sprite 僅 2 隻過 QA，剩 27 隻重製時若色票/比例不統一，會破壞遊戲視覺一致性。
- **影響**：高（直接影響玩家第一印象與品牌感）。
- **緩解**：
  1. 鎖定 1 張 style reference，先量產 3 隻試水溫。
  2. 通過小金式人設鍛造 SKILL.md 的審核閘才量產其餘。
  3. 每 5 隻做一次視覺一致性 regression（截圖比對）。

### R-02  任務狀態持久化邊界 case
- **風險**：任務 `active` ↔ `completed` 在玩家異常關閉（強制關閉分頁）時可能遺失，導致 TC-09 不通過。
- **影響**：中（玩家需手動重玩，會有客訴）。
- **緩解**：
  1. 任務狀態變更採「事件後立即落盤」而非批次。
  2. 啟動時做一次任務鏈完整性檢查（依 `prerequisites` 重建）。
  3. 對 `active` 任務加 30 秒自動存檔。

### R-03  效能（30+ sprite 渲染掉幀）
- **風險**：tile 與 sprite 全部用獨立 `<img>` 會造成 draw call 過高，行動裝置 FPS < 30。
- **影響**：中（行動玩家流失）。
- **緩解**：
  1. 合併為 sprite atlas，採用 `<canvas>` 一次性繪製。
  2. 視野外物件不渲染（frustum culling）。
  3. TC-04 設為 release gate，未達標不上版。

### R-04  NPC 觸發邏輯時序/重入
- **風險**：玩家在 NPC 對話框觸發動畫時又觸發戰鬥/任務，造成狀態機錯亂。
- **影響**：中（會閃退或卡死）。
- **緩解**：
  1. 引入全域 `interactionLock` flag。
  2. 所有 NPC/任務入口先檢查 lock。
  3. 異常時 fallback 至主選單並寫 log。

### R-05  persona 草稿繞過審核閘直接上 runtime
- **風險**：依 SKILL.md，persona 修改須先出草稿走 QA；但實務容易直接改 runtime 檔，導致規範失效。
- **影響**：高（治理層級問題）。
- **緩解**：
  1. 在 `persona_loader.js` 加上檔案 hash 校驗，與審核版對齊。
  2. CI 拒絕未經 QA sign-off 的 persona 進入 release branch。
  3. 每週隨機抽 1 隻守護者做全 persona 反查。

## 四、驗收閘門（Release Gate）

1. TC-01 ~ TC-09 全部 P0 通過（P1 至少 80% 通過）。
2. R-01 ~ R-05 全部有對應緩解措施並寫入設計文件。
3. 自動化覆蓋率（事件 hook 層）≥ 60%。
4. 截圖回歸比對（v0.x vs v0.y）視覺差 < 5%。
